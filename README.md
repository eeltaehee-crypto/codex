# BUSAFE

## 휴대폰으로 접속할 수 있는 사이트 배포

공개 HTTPS 주소를 만들려면 정적 호스팅에 게시해야 합니다. `site/index.html`은 바로 게시할 수 있는 사이트 첫 화면이며 별도의 앱 서버가 필요하지 않습니다.

### 가장 간단한 방법 — Netlify Drop

1. `busafe-site.zip`을 내려받습니다. 업로드 화면에서 폴더를 요구하면 압축을 풀어 `index.html`이 들어 있는 폴더를 선택합니다.
2. https://app.netlify.com/drop 에 Netlify 계정으로 로그인한 후 ZIP 파일 또는 해당 폴더를 업로드합니다.
3. 배포가 완료되면 표시되는 HTTPS 주소를 휴대폰의 Safari 또는 Chrome에서 엽니다. 사이트 주소를 공유하면 다른 휴대폰에서도 접속할 수 있습니다.

생성되는 사이트 주소는 호스팅 서비스에서 결정합니다. 이 저장소에는 임의의 공개 주소를 기재하지 않습니다. Netlify 계정의 사이트 설정에서 주소를 변경할 수 있습니다.

### 소스를 연결해 자동 배포

저장소를 Netlify에 연결하면 `netlify.toml`에 따라 `npm run build:site`로 생성한 `site/`를 게시합니다. Node.js 20.9 이상을 사용합니다. 수동으로 배포 파일을 갱신할 때도 같은 명령을 실행하세요.

HTTPS 사이트에서도 기록은 각 휴대폰의 해당 사이트 주소에 대한 브라우저 저장소에 보관됩니다. 다른 기기와 자동 공유되지 않습니다. 지정 기관은 사이트의 **내 정보 → 안전 담당 기관 연락처**에서 등록합니다. 로컬 파일에서 저장했던 기록은 새 사이트로 자동 이전되지 않습니다.

## 단일 HTML 버전

**`busafe.html` 파일을 브라우저로 열면 바로 실행됩니다.** Node.js 설치나 Next.js 서버 실행은 필요하지 않습니다. CSS, 앱 JavaScript, 아이콘 및 일러스트가 파일에 포함되어 있습니다. Pretendard 웹폰트만 인터넷 연결 시 로드하며, 오프라인에서는 시스템 글꼴로 모든 기능을 사용할 수 있습니다.

홈, 단계별 점검, 사진 첨부, 점검 기록, 관리자 현황 및 CSV 다운로드를 포함합니다. 점검 기록은 현재 파일/브라우저의 로컬 저장소에 저장됩니다. 파일 주소와 서버 주소의 저장소는 서로 다르며, 파일 위치를 바꾸거나 다른 브라우저로 열면 이전 기록이 보이지 않을 수 있습니다. 브라우저에서 로컬 파일의 저장소 접근을 제한하면 오류 안내가 표시됩니다.

QR 스캔 없이 차량의 설치 위치로 소화기를 선택합니다. 카메라는 선택 사항인 사진 첨부에만 사용합니다.

소스를 수정한 뒤 HTML을 다시 만들려면:

```bash
npm ci --cache /tmp/busafe-npm-cache
npm run build:html
```

실제 HTML 파일을 임시 로컬 정적 서버로 제공하고 외부 네트워크를 차단한 Chromium에서 검증하려면 `npm run test:html`을 실행합니다. 아래 Next.js 버전도 개발용으로 유지합니다.

버스 기사님을 위한 소화기 점검 웹 앱. Next.js App Router, TypeScript, Tailwind CSS 4, Lucide React, Motion을 사용합니다. 모바일 375px부터 데스크톱까지 대응합니다.

## 실행

Node.js 20.9 이상이 필요합니다. 이 환경에서는 Node.js 24로 검증했습니다.

```bash
cd /workspace/codex
npm ci --cache /tmp/busafe-npm-cache
npm run dev
```

일반 로컬 환경에서는 저장소 디렉터리에서 `npm ci`, `npm run dev`를 실행해 localhost의 3000번 포트로 접속합니다.

```bash
npm run build
npm start
npm run typecheck
npm test
```

## 사용 흐름

홈 → 점검 시작 → 소화기 위치 선택 → 압력 판단 → 사진·안전핀·외관·고정 상태 → 최종 확인 → 저장. 각 단계에서 돌아갈 수 있습니다. 모달을 닫으면 저장하지 않은 입력은 보존되지 않습니다.

- 압력은 제품에 표시된 정상 기준으로 사람이 판단합니다. 일러스트는 예시입니다.
- 압력 또는 추가 항목 하나라도 이상이면 이상, 그 외 확인 불가가 있으면 확인 불가입니다. 둘 다 정상 완료와 구분합니다.
- 차량에는 소화기가 두 대 있습니다. 각각의 최신 기록이 오늘 정상일 때 차량 전체 정상 완료입니다.
- 사진은 모바일 카메라/갤러리에서 선택하고 긴 변 1200px JPEG로 줄여 저장합니다. 미첨부 가능, 개별 파일 최대 20MB입니다.
- 점검 기록은 최신순으로 검색·필터·상세 조회·CSV 다운로드할 수 있습니다. 사진도 상세 화면에서 확인합니다.
- 관리자는 이상/확인 불가 보고 내용을 조회하고 정비·교체 완료 처리할 수 있습니다. 원래 점검 결과는 유지되며 재점검 결과를 대신하지 않습니다.

## 데이터와 보관

초기 차량 6대 및 점검 5건은 **시연 데이터**로 표시합니다. 직접 저장한 기록은 **로컬 입력**으로 표시합니다. 이름은 내 정보에서 변경 가능합니다. 시연 데이터 날짜는 최초 로드 시 현재 로컬 날짜를 기준으로 생성됩니다.

`lib/data.ts`에 도메인 타입, 시연 데이터, 결과 판정 함수를, `lib/storage.ts`에 데이터 저장 접근을 분리했습니다. 이후 Supabase 등의 저장소로 이 계층을 교체하고 사용자 인증·회사별 권한 및 서버 검증을 추가할 수 있습니다.

현재는 `localStorage`(`busafe.records.v1`, `busafe.profile`)만 사용합니다. 브라우저별로 분리되며 브라우저 데이터를 지우면 기록이 사라집니다. CSV에는 사진이 포함되지 않습니다. 용량 초과나 쓰기 제한으로 저장이 실패하면 입력을 유지한 채 재시도할 수 있습니다. 관리자 메뉴는 시연용이며 권한 인증이 없습니다. 민감한 실제 운영 데이터 보관용으로 사용하지 마세요.

보고 버튼은 **보고 내용을 로컬에 저장**합니다. 알림·이메일·관리자 서버 전송은 수행하지 않으며 화면에서도 이를 안내합니다. 실제 이상 발견 시 회사의 안전 절차에 따라 담당자에게 별도 연락하세요.

## 디자인

Pretendard, 코랄·연한 핑크·소프트 그린, 둥근 카드, SVG 버스/압력계 일러스트를 사용합니다. Pretendard는 jsDelivr에서 로드하며 오프라인에서는 시스템 글꼴을 사용합니다. 주요 공통 컴포넌트는 `components/busafe.tsx`, 일러스트는 `components/illustrations.tsx`, 디자인 토큰·반응형 스타일은 `app/globals.css`에 있습니다. reduced-motion 설정을 지원합니다.

## 브라우저 검증

서버를 3000번 포트에서 실행한 후 `npm run test:browser`로 실제 Chromium에서 모바일/데스크톱 흐름을 확인할 수 있습니다. 기본 Chromium 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경 가능합니다. 새 브라우저 컨텍스트를 사용하므로 사용자의 저장 데이터에 영향을 주지 않습니다. 화면 캡처는 `/tmp/busafe-desktop.png`, `/tmp/busafe-mobile.png`, `/tmp/busafe-admin.png`에 기록합니다.

## 이상 발견 시 관련 기관 연결

이상·확인 불가 결과 및 미조치 기록 상세에 관련 기관 연결 카드를 표시합니다.

- **소방청 · 소방서 안내**: 소방청 공식 홈페이지(`https://www.nfa.go.kr/nfa/`)를 새 창에서 엽니다. 관할 소방서를 자동으로 지정하지 않습니다.
- **지정 기관 전화 연결**: 내 정보에서 기관명과 연락처를 저장하면 `tel:` 링크로 전화 앱을 엽니다. 전화번호를 임의로 설정하지 않으며 브라우저에 저장된 연락처를 사용합니다.
- **긴급 상황**: 화재·연기 등 긴급 상황 안내를 펼쳤을 때만 `tel:119` 전화 연결 버튼을 표시합니다. 단순 점검 이상이나 교체 문의와 구분합니다.

전화 앱/외부 홈페이지로 이동하며 신고 접수나 기록 자동 전송을 수행하지 않습니다. 웹사이트 이동에는 인터넷 연결이, 전화에는 기기의 전화 기능이 필요합니다. 로컬 보고 내용 저장과 기관 연락은 별개입니다.
